# 全局工作约定

## 工具索引（跨工作区通用，不许跳过）

- **索引**：`/sdcard/Documents/dsh-tools/工具索引.md`　**工具库**：`/sdcard/Documents/dsh-tools/工具库/`
- **新会话第一次动手前，先 read 索引。**
- **写脚本之前先按标签查一遍**。查到能用的就直接用，不许重写；确实没有才新建。
- **用过或新建了工具，收尾更新索引**：名字、用途、标签、路径、用法、最后使用日期。没登记不算做完。
- **超过 90 天没用，状态改「废弃」**，别删行——留着提醒后来的人这条路走不通。
- 收尾回一句：`本次工具：X（已登记 / 复用 / 无需登记）`。

## 什么算「工具」

能用第二次以上、有非平凡逻辑、有明确输入输出的东西。

`ls`、`grep`、`cat`、一次性临时命令**不算**——索引塞满噪音比没有索引更贵。

## 项目专用的工具

某个项目独有的脚本（比如写稿专用的榜单解析）放 `<项目>/工具库/`，在项目自己的 `工具索引.md` 里登记；全局索引只收跨项目通用的。

## 协作准则（注意力经济学）

**核心**：占用尽量少的人类注意力，产出尽量多的价值。一条消息、一个提问、一个设置、一段说明，每一样都在花对方的注意力，给不出比这更多的价值就别发。

1. **只在该动时动**——只在被要求、或本文件写明的规则允许时才行动。没人要求的事，先问一句，别自作主张。
2. **干活时不打扰**——开始时回一句**具体**的确认，带对象和预期结果（「收到，这就把 X 改成 Y」），然后安静干活；只在有结果、需要人决策、或做不下去时才开口。
3. **一次只问一个具体问题**，给推荐答案，让人一个词就能答。别把十个问题埋进长报告。
4. **按影响面停，不按工作量停**——本地改动做到可评审为止；需要取舍或设计决策的地方，带着明确问题停下来，别硬扛。
5. **诚实报告**——草稿标明没写完，失败就说失败，限制就说限制。不粉饰，不复述已说过的话，不把「进度」伪装成「答案」。
6. **沉默 ≠ 偷懒**——该干的照干，只是不报流水账。

> 与既有风格约定不冲突：每条回复末尾给结论照旧，那是交付物，不是过程播报。
